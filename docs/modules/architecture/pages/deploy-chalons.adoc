== Procédure dédiées à l'application Châlons

== Déploiement


=== Générer des équipements dans l'hyperviseur
Pour associer et enrichir des équipements, il faut les générer à l'aide de la requête `create/update equipments` dans le dossier `provoly/hypervisor` de Postman.

=== Configurer et insérer les données dans Kuzzle
Il existe deux possibilités :

==== NodeRed
Le NodeRed déployé est configuré pour récupérer les mesures directement de Citylinks et les envoyer à Kuzzle.
Pour cela, il faut lancer les différents flux à l'adresse https://nodered.chalons-dev.provoly.net :

* `creation tenant`
* `integration armoire`
* `integration point lumineux`


==== Postman
Pour des données de tests, il est possible d'utiliser les requêtes dans le dossier `Kuzzle` de Postman:

* `Init`
* `Create asset/device`
* `Mesures`

NB: il faut s'assurer que le nom du tenant présent dans toutes les urls correspond bien à celui configuré dans provoly.
Pour l'environnement "chalons-dev", il faut que le tenant se nomme `connect-chalons`.



=== Créer les classes et les jeux de données

Lancer l'ensemble des requêtes présentes dans le dossier Postman :

- provoly/[chalons] init env/create

_Attention à choisir la bonne requête de paramétrage de la metadata geoKey car le slug des datasets et différents suivant les environnements._

=== Configuration du GeoServer

==== Se connecter avec les credentials de démarrage
Se connecter au cluster de l'environnement correspondant pour récupérer les identifiants de connexion


==== Créer un workspace "chalons"

image::geoserver-workspace.png[]

==== Créer un store "chalons"

Créer un store de type Provoly dans le workspace "chalons"

* Nom de la source de données : Provoly
* uri_ref: http://data-ref:8080/
* uri_virt: http://data-virt:8080/
* sso_uri: https://sso.chalons-\{environnment}.provoly.net/auth/realms/provoly
* client_id: provoly
* client_secret: dummy
* user: iamsuperadmin
* password: password
* chunkSize: 5000
* maxItems: 5000
* timeout: 60

==== Publier les couches

Les objets de configuration geoserver son stockées dans le https://github.com/connecte-chalons/chalons-hyperviseur[répertoire frontend]

Copier les icônes dans le Geoserver

----
# A lancer depuis le répertoire du projet
kubectl -n chalons-dev -c geoserver cp geoserver/icons geoserver-0:/opt/geoserver/data_dir/workspaces/chalons/styles
kubectl -c geoserver exec -it geoserver-0 -- chown -R geoserveruser:geoserverusers /opt/geoserver/data_dir/workspaces/chalons/
----

Créer un style `equipment` en utilisant le fichier `geoserver/equipment.sld`

Note: il faut sélectionner le fichier, cliquer sur "Charger" (en face) et re-sélectionner le fichier. Ensuite cliquer sur "Valider".

Publier la couche "xxxxxx_equipement-enrichi-mesure"

Cocher la case "Personnaliser les attributs" en attendant la correction du bug https://github.com/Provoly/provoly-geoserver-datastore/issues/46

Dans l'onglet "Publication" de la couche, choisir le style "equipment" par défaut

La mise à jour du style de la couche peut se faire avec la commande suivante :
----
kubectl -n chalons-dev -c geoserver cp geoserver/equipment.sld geoserver-0:/opt/geoserver/data_dir/workspaces/chalons/styles
----

== Reset d'un environnement

En prérequis, configurer une console Kuzzle pour un serveur sans SSL sur le port 7513, ainsi qu'une connection Postgres pour lancer des commandes SQL sur le port localhost:5435
Ensuite lancer les port forwards suivants :

[source, shell]
----
export CHALONS_ENV=chalons-dev
kubectl -n $CHALONS_ENV port-forward service/kuzzle 7513:7512
kubectl -n $CHALONS_ENV port-forward service/provoly-postgresql-rw 5435:5432
----
